# rmz4 <- rmz3-dev 函数同源匹配报告
## 方法
- rmz3-dev: 用 `rmz3-modern.elf` (nm 取符号->地址, objdump -d 取每函数反汇编) + `rmz3-modern.map` (每 .text 块 -> src/<子系统>.o) 得到 **具名函数 -> 子系统类别**。
- 两侧都做**归一化指令签名**: 只保留助记符(去 .n/.w)+寄存器操作数, 屏蔽立即数 / PC 相对字面量装载 / 分支目标 / 裸绝对地址 / .word 池。
- 精确匹配: 签名完全相等且指令数 >= 8。模糊匹配: difflib 相似度 >= 0.92 且指令数 >= 12(打 0.55 折)。
- 保守策略: 短函数不做精确同源(纯 push/pop/访问器易撞), 类别不纯按比例打折, rmz3 侧签名全局唯一额外加分。

## 已知误差来源
- **泛型短函数**: 引擎里大量 8~12 条的 getter/setter/task 调度同型, 不同子系统会撞签名; 已用长度门限+纯度打折压制, 但 mid 档仍可能错挂。
- **编译器差异**: rmz3-modern 用现代 gcc 重编, 与 rmz4 原 ROM(老 agbcc 风格)指令选择可能不同, 导致真同源函数签名不等 -> 漏配(降低覆盖率, 不产生错配)。
- **rmz4 专属内容**: rmz4 新增 boss/stage/cyberelf 在 rmz3 无对应, 必然未匹配, 属正常。
- **类别粒度**: category 取顶层子系统(boss/player/enemy..), 具体名(anubis 等)放 candidate 列, rmz4 同名实体未必存在, candidate 仅作线索。
